## Rules that do not change

- **Production push.** Before ANY push to production, ask Michiko in the chat for the prod-push password, every time. Never store it anywhere. After a push, run `git log -S"<password>"` (expect 0).
- The prod repo is attached through the GitHub connection. Never commit github_token.txt. Do not unset the proxy or bypass TLS.
- **Promote:**
  1. `git fetch prod`
  2. `commit-tree HEAD^{tree} -p prod/main`
  3. `git push prod <commit>:main`
  4. Verify the trees match.
  5. Log the promote in progress.txt without the password.
  6. Sync progress.txt to Drive.
- **Style:**
  - No em dashes.
  - Plain language.
  - Flag uncertainties.
  - No VERIFY in public listings.
  - When she asks whether or how something could be done, answer and ask "should I go do this?" first.
- **Working notes:**
  - At most two OCR streams.
  - A background committer loop keeps the stop hook quiet.
  - Readers save after each issue.
  - If the usage limit stops a reader, resume it with SendMessage after the reset rather than starting a new one.
- **Drive sync:** tar the changed files, split into 12 MB parts, commit the parts into `_to_delete/`, then on the device extract to a temp folder and `cp` over the working folder. Deletes are not permitted on the device. Note from this session: `device_commit_files` wrote files up to about 14 MB straight into the Drive working folder (its limit is 400 MB per file), so for a few changed files the tar and split step is optional; the split method still matters for sending many files at once.
